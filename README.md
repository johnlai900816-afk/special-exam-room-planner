# 資源班管理系統

國中資源班共用的一套系統：一份名冊，排課、點名、段考、IEP 會議、通知單都讀它。

純前端，沒有後端。內建的是**虛構範例資料**。

## 畫面

左邊是選單（手機在上方），每頁頂端是頁名和分頁。說明文字收在「？」裡，點開才看到。

### 管理者

| 選單 | 內容 |
|---|---|
| 今天 | 今天的課（現在這一節標出來）、待辦（衝突、還沒排、沒分組、沒有個管、本月到期、IEP 回覆進度、備份提醒）、快速動作、資源班老師的節數與個案數 |
| 學生 | 名單（搜尋；篩選年級、個管、本月到期、只看我的；勾選後一起指定個管）、**個案頁**（基本資料、私密欄位、組別與個人課表、考評服務、出缺席、IEP 會議）、個管分配 |
| 排課 | ① 開課 ② 編組 ③ 排課表（一鍵試排、草稿與確定、拖曳、AI）④ 輸出（各種課表、鎖課表、抽離表） |
| 段考 | 段考考場（exam.html）：名單與服務、考程與教室、排考場、輸出、查考場連結 |
| IEP 會議 | 調查（建立調查 → 建立並產生 QR；同一頁有 QR 與連結、①回覆 ②排定 ③通知）、直接開會（畫面在 iep.js） |
| 點名 | 點名（照課表帶出這一節的學生，可掃學生卡）、紀錄、導師週報；學生卡從點名頁進去 |
| 統計 | 老師工作量、教室使用、鎖課異動（extras.js） |
| 設定 | **學校資料**：① 匯入 Excel ② 全校課表 ③ 老師與任課 ④ 不排課時段 ⑤ 教室與作息 ⑥ 排課規則 ⑦ 學年交接檢查／**帳號與共用**／**資料與備份**（下載、加密備份、還原、自動保留的版本、新學期、公用電腦、全部清空）／**AI**（Gemini） |

右上角「以老師身分看」可以預覽老師看到的畫面。

### 老師

登入後信箱被綁定到名冊裡的一位老師（或單機時由管理者切換），選單只剩：今天、我的學生、我的 IEP、點名、我的設定。畫面由 `teacher.js` 提供。

**已知限制**：雲端目前是一整份資料，老師登入後畫面只顯示自己的，但技術上讀得到整份。要做到資料庫層級的隔離，要搬到 Next.js 版的分筆資料（web/MIGRATION.md）。

舊網址會自動轉到新的位置，例如 `#roster/stu` → 學生、`#sched/off` → 設定 › 不排課時段、`#roster/backup` → 設定 › 資料與備份。

## 各部分怎麼連在一起

1. **學生只有一份**。在學生頁新增、改名、刪除，段考會跟著變；在段考匯入考評服務名單新增的學生，也會回到名冊。
2. **監考老師自動帶入**。身分是「資源班」的老師會成為段考的監考老師；應授課節數沒填的，帶入排課結果的每週節數。
3. **一份共用名單**。登入共用之後，可以使用的老師名單同時管名冊、排課與段考。
4. **備份是一個檔**。下載的備份檔含名冊、排課、段考、通知單與點名紀錄。

從名冊刪除學生，段考裡他的考評服務會一起清掉。只在段考刪除的話，他還在名冊裡；這次不排的學生請用段考的「排入」勾選。

## 排課的順序：老師優先

準備資料在「設定 › 學校資料」（任課老師、不排課時段都在這裡），排課只有四步：

1. **① 開課**：填每位資源班老師的基本鐘點，替他開課（科目、年級、每週節數、型態、固定時段、教室）。可以「貼上課程一覽表」或「貼上分組表」一次帶入；組名相同的課是更新不是新增。
2. **② 編組**：「學生 × 科目」的表，每格選「不上」、「待安排」或直接指定某一門課；「自動編組」會把待安排的學生放進同科目、同年級、不衝堂、人數最平均的課。
3. **③ 排課表**：「一鍵試排」排出草稿，和正式課表並排比較，滿意再「確定採用」；可以拖曳、固定、只排某個年級。上方的小膠囊提醒任課老師、不排課時段、待安排還缺什麼。「更多」裡有用 AI 排（複製貼上或 Gemini）、解除固定、清空。
4. **④ 輸出**：見下面。

## 不排課時段分幾層

排課時會把下面每一層疊在一起避開。

| 層 | 用在哪裡 |
|---|---|
| 全校 | 所有組別都不排，例如全校週會 |
| 年級 | 各年級社團、班會時間不同時，分開點 |
| 學生群組 | 自己命名的一群學生，例如技藝班 |
| 班級、學生個人 | 只有某一班或某一位學生不能被抽離 |
| 老師 | 資源班老師，以及學生原班的任課老師 |

每一層都可以「從別的對象複製」。

## 課表輸出（排課 › ④ 輸出）

資源班老師課表、給教務處的鎖課表、鎖課清單、給導師的班級抽離表（一班一頁）、給任課老師的抽離名單（一位老師一頁）、學生個人課表、學生抽離一覽、個管個案一覽（一位個管老師一頁）、組別總表。

1. 所有表格的表頭都在 `<thead>`，印很多頁時每頁都會重複表頭。
2. **給導師的班級抽離表**：每一節寫「原班 ○○課 → 資源班 ○○（老師・教室）」，彈性鎖課時照配鎖課的結果寫原班實際鎖的科目（可能和資源班不同科）；外加課另外標「外加」，不鎖課的課寫「原班照常上課」。表頭有導師、個管老師與實施日期，最下面有「製表、日期、導師簽收」。
3. **給任課老師的抽離名單**：照鎖課找出每位原班老師，列出哪一班、哪一節、哪些學生被抽離、去上什麼。
4. **個管個案一覽**：每位個管老師的個案、所在組別、每週節數與上課節次（不印私密欄位）。學生個人課表的表頭也會寫個管老師。
5. 鎖課表和鎖課清單的標題有列印日期，最下面有「製表、日期」簽名欄。組別總表的型態欄照課的設定寫抽離、外加或不鎖課。

另有兩種照板橋國中原本的格式做的版面：

1. **總課表**：一張橫式的表，列是節次，欄是星期再分教室，每格是「科目第一個字＋組別代號＋老師的姓」（同姓的寫名字），顏色代表老師；格子另有 `.t0`～`.t11` 的樣式（依老師在 `M.rts` 的順序），印成黑白也分得出老師。組名帶著科目的（8A國文）在表上只顯示代號（8A）。可以填實施日期。
2. **學生個人課表**：一位學生一頁，列出全部節次，有課的格子是色塊（科目、老師、教室），顏色依科目。可以改課表名稱、只印某個年級。

## 超鐘點與認領

1. **老師的節數**：基本鐘點（hours）－減授（reduce，原因寫在 reduceNote，例：組長）＝應授。超過應授的是超鐘點。外加課預設另外列，不算超鐘點（排課規則可以打開「外加課算進超鐘點」）。
2. **意願**：每位老師填「每週最多超幾節」（otMax，0＝不願意）、想教的科目和年級、不想教的科目。老師在「我的設定 › 超鐘點意願」自己填，管理者在「設定 › 學校資料 › 老師與任課」也可以改。全校每人每週上限在「排課規則」（otCap）。
3. **開課頁**：上面一行寫「需要幾節、應授合計幾節、缺幾節」，每位老師寫應授、已開、超鐘點（超過上限標紅）。「建議分配」把沒有老師的課分給還有餘裕的老師：一定遵守意願、全校上限、不想教的科目、老師不排課時段太多就不給；盡量先補沒滿應授的、超鐘點平均、想教的優先、同一位學生的課給同一位老師。勾選的才套用，套用前先存一個版本。
4. **認領**：還是沒有老師的課是「待認領」。老師在「今天」和「我的設定」看到，按「我可以帶」送出；管理者在開課頁核准或不核准（兩位以上認領時選一位）。沒有人認領的課列在「今天」的待辦：「這 N 門要找兼代課老師」。
5. **每月超鐘點**（統計 › 老師工作量）：上課日是星期一到五，扣掉放假日（排課規則）和實施日期以外的日子。一週一週算：那一週在這個月裡的上課日照課表的節數，減掉「應授 × 上課日數 ÷ 5」，少於 0 算 0、最多算到每週超鐘點；本月是各週相加。可以印成 A4 直式的表（教師、應授、每週超鐘點、本月上課日、本月超鐘點節數、備註，下面有承辦人、教務主任簽名欄）。

## IEP 會議時間調查

1. **建立調查**：選學生（老師只列自己個管的）、日期（預設回覆期限後的兩週）、節次（預設全部一般節次）、回覆期限（預設 5 天後），出席名單自動帶入。
2. **承辦有課的節次先拿掉**：承辦的個管老師有資源班課、原班課、登記不排課、已排定的 IEP 會議的節次，不會問任何人（畫面寫「已排除你有課的 N 節，剩 M 節可選」）。特殊情況可以在「調整名單／時段」勾「有課的節次也問」。
3. **挑時段**：同一個畫面有日期 × 節次的格子；有全校課表時格子寫學生原班在上什麼，主科（國語文、英語文、數學，D.settings.iepAvoidSubj）淡黃、綜合活動、彈性、社團、輔導、班會（D.settings.iepPreferSubj）淡綠，「勾選建議時段」一次勾好。有勾就只問勾的；沒勾就全部沒課的都問。
4. 按「建立並產生 QR」（有雲端時同時發布連結），就到這次調查的頁面：印 QR 小單（一張 3、4 或 6 份，記住上次選的）、複製全部連結（貼到 LINE）、每個人已填／未填、複製、重新產生。下面依序是 ①回覆 ②排定 ③通知。
5. **公開頁不寫任何人哪一節有課**：發布的資料只有稱呼、學生班級座號、日期範圍、要問的節次。排時間時仍然把必要出席的人有課的節次當成不行（只在 app 裡）。

## 手機

版面會自動改成上方選單；不排課時段改用下拉選單選對象；排課板用「點一下組別、再點要放的格子」移動。

## 點名

1. **照課表點名**。打開「點名」會自動跳到現在這一節，列出該到的學生；也可以選其他日期補登。
2. **三種簽到方式**。點名字、用鏡頭掃學生卡、或在輸入框打姓名或班級座號（例 70103）。接電腦的條碼掃描器等同在輸入框打字。
3. **狀態**。點一下簽到，再點一下簽退；上課超過 5 分鐘（可調）才到算遲到；「⋯」可以改成請假、缺席或加備註。過了下課時間還沒簽到的顯示未到。
4. **出缺席紀錄**。可選今天、本週、本月或自訂期間，列出每位學生的應到、實到、遲到、請假、缺席與出席率，點學生看明細，可列印或複製。只計算有點過名的節次，所以放假不會被算成缺席。第一次點某一節時，會在紀錄裡存下當時的名單（`_roster`）和組名、節次名稱（`_info`）：學期中才加入的學生不會被算成之前每節都缺席；新學期清掉組別後，統計也還在。舊紀錄沒有名單的，只從學生在那一組第一次有紀錄的那天開始算。
5. **公開提醒與私密備註**。個案頁的「公開提醒」會在簽到時顯示給學生看；「個管私密備註」、IEP 會議日期、下次檢討日、鑑定有效期限放在名冊的「私密欄位」（勾選才顯示），不會出現在簽到畫面，也不會印出來。舊資料的備註第一次開啟時會先搬到私密備註。總覽會提醒本月到期的日期。
6. **學生卡**。每人一張 QR 卡，可依班級或組別篩選後列印。
7. **多台裝置**。登入共用後，點名紀錄一天存一份，逐筆合併寫入，兩台裝置同時點名不會互相蓋掉。

## 衝堂檢查與手動調整

排課頁上方有一列「衝堂檢查」，每次調整都會重新算，分成：老師、學生、原班兩科、任課老師、教室、不排課時段、還沒排。有問題時上面會列出紅字，點一下就跳到那一節。

點一下課表上的組別，會出現編輯列：可以改這一節的教室、固定或解除固定、拿下來，或點別的格子移動（綠色是不會衝堂的位置）。放到會衝堂的位置也放得進去，只是會被標出來。

在「不排課時段」改了設定後，如果已經排好的課落在新的不排課時段，會立刻提醒。

## 排課規則

下面每一條都可以在「設定 › 學校資料 › 排課規則」開關或改數字。


一定要遵守的：

1. 資源班老師不排課的時段不排，同一節不會有兩組。
2. 學生同一節不會在兩組。
3. 抽離課：這一組學生原班的任課老師，只要有一位不排課，那一節就不排。
4. 抽離課：同一個班同一節不會被要求上兩科。
5. 抽離課：同一位普通班老師同一節不會被兩個班同時鎖課（可在「設定 › 學校資料 › 排課規則」關閉）。
6. 外加課只排在勾了「外加時段」的節次，抽離課只排在一般節次。
7. 全校共同不排的時段不排；同一節的組數不超過教室數。

盡量做到的（排不開時可以超過，畫面上寫「盡量不超過」）：同一組一天只上一節；資源班老師每天節數平均、不連上超過三節；學生一天被抽離不超過三節。

## 鎖課方式

抽離課要請教務處把原班的課「鎖」在同一節。各校做法不同，在「設定 › 學校資料 › 排課規則」選：

1. **原班和資源班同一節上同一科**：資源班上國文時，學生的原班也一定要排國文。任課老師不排課的時段、同一位老師教的兩個班，都會直接限制排課。
2. **彈性鎖課**：先排資源班課表，再替每個「有學生被抽離的班級 × 節次」配一科來鎖。優先鎖同一科；鎖不到（老師不排課、被別班鎖走、該科節數用完）就改鎖其他主科；都不行就列為鎖不到。同一位老師同一節只會被一個班鎖。可以設定各科每週最多鎖幾節，以及鎖到只剩 1 節時要保留連堂的科目（系統會在旁邊多鎖一節，或少鎖一節）。

彈性鎖課時，一鍵排課排完會再做一次收尾，把鎖不到的節次換到鎖得到的時段。排課頁的衝堂檢查列會顯示「鎖不到課 n／總數」；「課表輸出」有鎖課表、鎖不到的清單，以及和教務處試算表相同欄位的鎖課清單。

課的型態有三種：抽離（要鎖課）、外加（只排早自習這類時段）、不鎖課（排在一般節次，但不需要原班配合，例如社會技巧）。

班級層級的時段分兩種：「不能被抽離」和「不能鎖課」（例如導師時間、本土語、特色課程）。後者只影響鎖課，不鎖課的課仍然可以排。從 Excel 帶入班級不排課時，預設全部當成「不能被抽離」（完全鎖定，不會排課進去）；也可以改成只鎖定勾選的原因（系統會列出表裡出現過的原因）。

已經手排好的鎖課（特教鎖課需求的「資料輸入」或「資料輸出」）可以一起上傳或貼上，排課時會盡量排回這些節次，配鎖課時優先用手排的老師；不想沿用就在「學期初匯入」清除。教務處整理好的班級不排課、教師不排課，可以在「不排課時段」頁按「貼上不排課表」整張帶入。

## 每學期怎麼更新資料（學校自己來）

「設定 › 學校資料 › 匯入 Excel」放每學期要帶進來的表；「設定 › 資料與備份」放下載備份、從備份檔還原、自動保留的版本、開始新學期、全部清空。

1. **開始新學期**（資料與備份）：勾選要清掉的部分（排課結果、課程、任課老師、班級不排課、老師不排課）。新學年可以勾「升年級」：七年級變八年級、八年級變九年級（701→801），九年級學生畢業移出名冊；因為班級號碼會變，課程、任課老師、班級不排課、全校課表和各班導師會一起清空，之後要讀入新學年的全校課表。
2. **上傳學校的 Excel**：一次選好幾個檔案，系統自己認出學生名單、任課老師名單（教務處的教師名單）、課程一覽表、班級不排課、教師不排課，其他工作表略過。列出來之前會先試算一次，帶不出資料的工作表不會列。Google 試算表要先下載成 Excel。檔案只在瀏覽器裡讀，不會上傳。
3. **資料清單**：每一種資料目前有多少、來自學校的哪一份表，每列都有「貼上」可以單獨更新。
4. 補上資源班老師自己的不排課時段，再到排課頁按一鍵排課。

各頁也都有對應的「貼上」：學生名單（可多一欄個管老師、一欄備註）、任課老師名單（老師頁與任課老師頁）、課程一覽表、不排課表。老師頁另有「移除沒用到的任課老師」。

匯入時要注意的幾件事：

1. **學生名單**：同班同名的會更新；座號相同但姓名不同（可能是轉入或換座號）不會蓋掉原本的學生，而是另外新增，再列出來，每筆都有「刪掉舊的」按鈕。名冊裡沒有的個管老師會自動建成資源班老師，並列出來。有「導師」欄時另外存成各班導師。名單上的「備註」存成個管私密備註。
2. **老師的名字**：所有匯入（學生名單的個管老師、任課老師名單、課程一覽表、不排課表、手排鎖課）都用同一個 `normName()` 比對，去掉空白和「老師、主任、組長、導師、校長、教師」，所以「王」「王老師」「王 老師」是同一位，不會重複建立。
3. **課程一覽表重貼**：表上有名字對不到名冊時，原本在課裡的學生先留著，標「表上沒找到」列出來；全部都對得到才照表更新名單。授課教師寫兩位（「王老師、李老師」或「王/李」）時，第一位當授課老師，其他的列出來。
4. **從課裡拿掉學生**：如果他這一科已經沒有別的課，會問「是不上這科了，還是改成待安排？」，不然一鍵排課會把他放回去。
5. **刪除**學生、老師、課、教室之前會自動保留一份版本，刪完 8 秒內可以按「復原」。刪除有個管學生的老師時，會先問由誰接手。

### 改壞了怎麼辦

每天第一次修改，以及匯入、開始新學期、一鍵排課、刪除、還原之前，這台電腦都會自動留一份版本（最多 12 份，存在瀏覽器的 IndexedDB，總量約 30MB；不支援時改存 localStorage，約 1.5MB），在「設定 › 資料與備份」可以回到任何一份。「公用電腦模式」不保留版本。這是存在瀏覽器裡的，換電腦或清除瀏覽器資料就沒了，所以仍要定期按「下載備份檔」；總覽會在超過 14 天沒下載備份時提醒。

## 學校自己的雲端

想讓幾位老師共用同一份、又不依賴別人的帳號，可以讓資料存在學校自己的 Firebase（免費方案即可，建議用學校或處室的公用 Google 帳號建立，人事異動時交接帳號就好）。不用改程式，在網站裡設定：

1. 按左下的「備份與還原」或「共用」，打開「學校自己的雲端」，照裡面的步驟做：建立 Firebase 專案、建立 Firestore（asia-east1）、貼上「複製安全規則」的內容並發布、啟用 Google 登入並把網站網域加入已授權網域、把 firebaseConfig 貼進來按「套用」。
2. 「複製安全規則」會先問主持人的 Gmail，填進規則最上面的 `adminEmail()`：只有這個帳號能第一次登入、建立共用名單並成為主持人。用這個帳號登入後，系統會問要不要把這台電腦的資料傳上去當第一份。
3. 按「複製給同事的設定連結」傳給同事：連結裡帶著設定（`#cloud=…`），同事點開時只會把設定**帶入**「學校自己的雲端」表單，並顯示專案名稱與登入網域；要同事自己核對、按「套用」並再確認一次才會生效。之後用自己的 Gmail 登入，主持人把他加進共用名單。
4. 使用學校自己的雲端時，左下會一直顯示「使用學校雲端：專案名稱」。第一次連到一個新專案時，如果這台電腦已經有資料，會先問要不要改用雲端的資料，並先自動保留一份。

設定連結只接受 Firebase 自己的登入網域（`專案.firebaseapp.com` 或 `專案.web.app`）。不認得的專案名稱，請不要按套用。

### 安全規則（firestore.rules）的更新紀錄

這一版的規則和之前的不一樣，**要自己到 Firebase 發布一次**才會生效（網站不會、也不能幫你改）：

- 第一次建立共用名單（`config/access`）只限 `adminEmail()` 這個信箱，避免別人搶先登入變成主持人。已經有共用名單的專案不受影響。
- 主持人可以把主持人交給名單裡已經有的成員（共用名單裡的「交給他當主持人」）。
- 共用名單最多 100 人，只能有 admin、emails、viewers、link 四個欄位；link 只能是 32 碼的亂數或空白。
- `rc/main`、`exams/main`、`exams/notice` 不能刪除；只能有 json、by、at、rev 欄位，json 小於 1MB，by 一定是自己、at 一定是伺服器時間；有帶 rev（版本號）就一定要是上一版加一。
- `rc` 底下只能建立 main、presence 和 `att-年-月-日`（點名紀錄）；`exams` 底下只能建立 main、notice、presence。
- `rc/presence`、`exams/presence`（誰在線上）：每個人只能改自己那一格，內容只能是自己的信箱、名字、時間。
- 免登入檢視連結 `view/鑰匙`、`view/鑰匙_班級`：只能讀單一文件、不能列出，而且文件一定要有到期時間 `exp`，過期就讀不到。

**發布步驟（主持人自己做）：**

1. 打開網站，「共用 › 學校自己的雲端 › 複製安全規則」，輸入主持人的 Gmail（已經有共用名單的專案，填現在的主持人即可）。
2. 到 console.firebase.google.com → 你的專案 → Firestore Database →「規則」分頁，把內容全部換成剛才複製的，按「發布」。或者在這個資料夾把 `firestore.rules` 裡的 `CHANGE-ME@example.com` 改成主持人的 Gmail，再執行 `firebase deploy --only firestore:rules --project 你的專案`。
3. 在「規則」分頁的「規則遊樂場」試一次：用成員帳號讀 `rc/main` 應該可以，未登入讀 `rc/main` 應該被拒絕。
4. 發布後，請所有老師重新整理網頁（舊版網頁沒有版本號，仍然寫得進去，但不會偵測衝突）。
5. 段考考場頁的檢視連結要寫入 `exp` 才讀得到；舊的連結在新版段考頁重新產生之前會失效。

設定存在各台電腦的瀏覽器裡（`school.js` 讀），會取代網站內建的設定；也可以改成「不使用雲端（單機）」或改回內建。Firebase 的網頁設定本來就是公開的資訊，資料的安全靠登入與安全規則。

## 全校課表與段考交卷名單

「設定 › 學校資料 › 全校課表」可以選學期初拿到的全校課表 PDF（每班一頁、底下有「科目、老師、節數」統計的那種），七、八、九年級的檔案可以一次選。

文字 PDF 直接讀。掃描成圖片的 PDF 會在瀏覽器裡用文字辨識（Tesseract），只辨識底下的統計和左下角的編號，一頁大約一秒，第一次要下載約 20MB 的辨識資料。辨識出來的名字會對照名冊、任課老師和教師不排課裡的老師名字；整份一起讀時，也會看同一科在別班是哪位老師，來補認錯字。還是認不出來的標成橘色，點班級會看到截下來的統計圖，對照著改。

比對的規則（`ttNameFix`、`ttSubjCand`）：

1. 名字用編輯距離比：少一個字、多一個字（蔡珊→蔡依珊）或形近字（已／己、未／末、珊／姍、于／於、婷／停、髓／體、依／侑…，見 `TT_LIKE`）算小錯，而且要明顯比第二像的近，才自動改。只差一個普通的字（陳美華和陳美玲）只當「推測」，標橘色讓人確認；只對上一個字的不猜。推測的名字存成 `x[2]=2`，不會被當成確定的老師拿去用。
2. 兩個字的科目要完全相同或只差形近字才認（髓育→體育）；差一個普通的字（家長、生活、理由、體重）一律標待確認。三個字以上的科目差一個字（類語文），要老師確定教這一科才算數。
3. 節數超過 9 不截斷，標待確認。
4. 班級編號接受三碼（年級是第一碼）或四碼（10～12 年級，年級是前兩碼）。
5. 「班級」欄改成另一個已經有課表的班級時，會先問要不要蓋掉。

讀完會列出每班國英數社自的老師，並且和學生名單對照：名冊有學生但課表沒有的班級、任課老師和課表不一樣的格子，以及每位學生各科的老師。按「用課表更新任課老師」可以把國英數理的任課老師一次改成課表的。

段考頁的「服務表」多了「交卷名單」：每一科一張 A4 直式，照學校原本的紙本格式，依年級分三欄，每位學生後面有「□已交□未到」和批閱教師。批閱教師從全校課表找（作文、國文找國語文老師，社會找歷史、地理、公民老師，自然找生物、理化、地科老師），沒有課表時用各班任課老師，都沒有就留白讓學校手寫。

## 教室與備用教室

「設定 › 學校資料 › 排課規則」可以改教室名稱、新增或刪除教室。勾「備用」的教室平常不排：同一節最多排「沒勾備用的教室數」組，真的排不下才會用到備用教室，總數不會超過全部教室數。分配教室時也是先用平常的，最後才用備用的。

## 怎麼開

需要用網頁伺服器開，不能直接點兩下 `index.html`（段考考場那一頁要和外殼互相讀資料，瀏覽器不允許本機檔案這樣做）。

1. 放到任何靜態網站空間（GitHub Pages、Firebase Hosting、Netlify 都可以）。
2. 或在這個資料夾執行 `python -m http.server 8765`，再開 `http://localhost:8765`。

## 登入與多人共用

預設是單機模式，資料只存在該瀏覽器。要讓幾位老師共用，每間學校做一次：

1. 到 Firebase 主控台建立專案，啟用 Authentication 的 Google 登入，建立 Firestore 資料庫。
2. 在專案設定新增網頁應用程式，把設定貼到 `firebase-config.js`，取代 `null`。
3. 部署資料庫規則：在這個資料夾執行 `firebase deploy --only firestore:rules --project 你的專案`。
4. Authentication 的「已授權網域」加入網站的網域。
5. 打開網站，用規則裡 `adminEmail()` 的信箱登入成為主持人，再加入其他老師的 Gmail，選「編輯」或「檢視」。

如果這間學校已經在用「段考特殊試場排列機」的 Firebase 專案，可以直接用同一個專案的設定：`firestore.rules` 已經包含排列機原本的規則，共用名單也是同一份。注意：部署規則會取代該專案現有的規則。

登入後會改用雲端的那一份（第一次連到新專案、這台電腦又有資料時會先問，並先自動保留一份）；雲端還沒有資料時，會先問要不要把這台電腦現在的資料傳上去。

雲端的名冊與排課有版本號：存檔時如果雲端已經被別人改過，不會直接蓋掉。兩人改到不同部分（例如一人改名冊、一人改排課）會自動合併；改到同一部分會問後存的人要保留哪一份，兩份都會先自動保留一份。存檔失敗會自動重試；沒網路時改的內容會記在這台電腦，下次連上先比對版本再存。一份資料最多約 1MB，超過 700KB 會提醒。

登出時可以勾「同時清除這台電腦上的資料」。用過雲端的電腦沒登入時，畫面不會顯示學生資料。

## 資料與隱私

**收集哪些資料：** 學生的班級、座號、姓名、個管老師、考評服務與備註；老師姓名與不排課時段；課程、排課結果；點名紀錄（簽到、簽退時間與備註）；段考考場與通知單內容。登入共用時，另外記錄老師的 Google 信箱、顯示名稱與最後上線時間（誰在線上）。

**存在哪裡：**

- 單機：只存在這台電腦的瀏覽器（localStorage，自動保留的版本在 IndexedDB）。
- 共用：存在學校自己的 Firebase 專案（或網站內建的專案）的 Firestore，只有共用名單裡的帳號讀得到；同時這台電腦也留一份。
- 讀 Excel、課表 PDF、文字辨識都在瀏覽器裡做，檔案不會上傳。

**保存建議：** 每學期結束、資料不再需要時，請下載加密備份後「全部清空」（共用時由主持人做），並在學校的公用電腦上按「清除這台電腦上的資料」。學校的公用電腦請開「公用電腦模式」：不保留版本，Google 登入只在這個分頁有效（關掉分頁就登出），登出時預設清除資料。

**備份檔：** 一般備份檔是**沒有加密的文字檔**，含學生姓名與特教資料，任何人拿到都打得開，請不要上傳到公開的 repo、網站或群組。要存到隨身碟、雲端硬碟或寄出去，請用「下載加密備份檔」（AES-GCM，密碼經 PBKDF2 31 萬次），密碼忘了就打不開。

**外部服務：** 網頁字型從 Google Fonts 下載，Google 會看到使用者的 IP 位址與瀏覽器資訊（不會看到學生資料）。Firebase、讀 Excel、PDF、QR Code 與文字辨識的元件從 CDN（www.gstatic.com、cdn.sheetjs.com、cdn.jsdelivr.net、cdnjs.cloudflare.com）下載，都有固定版本與檢查碼（SRI）：主畫面、段考頁、IEP 公開頁都一樣，CDN 上的檔案被換掉時瀏覽器會拒絕執行。**例外：** 文字辨識（Tesseract）主程式有 SRI，但它執行時自己再下載的 worker、wasm 和中英文辨識資料（traineddata）沒辦法加檢查碼；只有讀「掃描成圖片的課表 PDF」時才會用到，介意的話請改用文字 PDF。

### 做到的保護

- **要登入才看得到：** 雲端的資料只有共用名單裡、信箱經 Google 驗證過的帳號讀得到；用過雲端的電腦沒登入時，畫面不顯示學生資料。
- **權限分三種：** 主持人（管名單）、編輯、檢視；檢視的人存不進去（資料庫規則擋）。
- **老師只看到自己的：** 綁定老師的帳號登入後只有「我的」頁面：自己個管或有教的學生、自己的 IEP 調查、自己的課。個案頁只開得了自己的學生；私密欄位（個管備註、IEP 與鑑定日期、家長聯絡紀錄、段考服務）只有個管和管理者看得到。老師身分不能下載備份、還原、清空或改雲端設定。綁定的老師被刪掉時顯示「找不到綁定的老師，請洽管理者」，不會變成管理者。
- **公用電腦模式：** 登入只存在這個分頁（關分頁就登出，新開的分頁要重新登入）；不保留版本；資料都存上雲端後關掉分頁會清掉這台電腦上的資料；登出時預設清除。
- **登出或「清除這台電腦上的資料」會清掉：** 名冊、排課、點名、段考考場、通知單、自動保留的版本、IEP 連結的鑰匙、「我是哪位老師」，以及 AI 的金鑰、設定與使用紀錄。外觀設定和學校雲端設定會留著。
- **IEP 線上調查：** 公開頁只經過 Cloud Functions，看不到資料庫；連結的鑰匙只存在發布的那台電腦，共用資料裡只有雜湊；回覆期限一過就打不開；結束調查會刪掉線上的連結與回覆。同一個連結、同一個 IP、全部加起來都有次數上限（IP 取 Google 前端記下的那一個，換標頭繞不過）。
- **查考場連結：** 換新或關閉連結後，舊連結馬上打不開（資料庫規則只認目前的鑰匙）；班級連結只有那一班、姓名遮一字。
- **AI：** 不在瀏覽器放金鑰（代理模式）；送出前和伺服器端各把姓名換成代號一次；只能用 flash、flash-lite、pro 系列的模型，不能開工具（例如上網搜尋）；每人有使用次數上限；稽核紀錄只記題目的雜湊。
- **畫面安全：** 學生、老師、課程、教室、節次的 id 只能是英數字、底線、減號，不合格的會自動換掉（備份檔裡有不合格的就不還原），畫面上的按鈕不再把資料直接拼進程式碼。

### 還做不到（請知道這些限制）

- **老師畫面的隔離只在畫面上：** 雲端的名冊是一整份，綁定老師的帳號技術上還是讀得到整份（例如懂程式的人打開瀏覽器的開發者工具）。要做到資料庫層級的隔離，要搬到 Next.js 版的分筆資料（web/MIGRATION.md）。
- **「編輯」權限的人可以改、也可以蓋掉整份：** 包含名冊、排課、點名，也能讀到別人的私密欄位。只把編輯權限給信任的人；改壞了可以從「自動保留的版本」或備份找回。
- **關掉分頁不等於登出：** 沒開「公用電腦模式」時，Google 登入會一直留在這台電腦，下一個人打開網站就是你的身分。學校的公用電腦一定要開公用電腦模式（它會改用只存在分頁的登入），或用完按「登出」。
- **全校的查考場連結有全部學生的全名：** 只給特教組或行政，不要傳給導師或貼到群組；導師請給「某班專用」的連結（姓名遮一字）。
- **AI 的資料會送到 Google：** 代理模式用 Vertex AI，`AI_VERTEX_LOCATION` 預設是 `global`（Google 自己決定在哪個區域處理，不一定在台灣）；要固定區域請改成例如 `asia-east1`（新模型可能還沒有）。姓名雖然換成代號，班級、課程、時段等內容還是會送出。直接用金鑰的模式，金鑰存在這台電腦的瀏覽器裡。
- **App Check 還沒開：** 公開頁（IEP 調查）和 AI 代理目前沒有開 Firebase App Check。要開的話：Firebase 主控台「App Check」註冊網站、建立 reCAPTCHA Enterprise 金鑰；在 `school.js` 或 `firebase-config.js` 設 `window.FIREBASE_APPCHECK_KEY='金鑰'`（iep.html 已經會讀）；觀察一段時間主控台的「已驗證要求」比例正常後，Functions 設環境變數 `IEP_APPCHECK=enforce` 重新部署，Firestore 在主控台按「強制執行」。主畫面（index.html、exam.html）也要另外載入 app-check 並啟用後，才能對 Firestore 強制。
- **IEP 連結換電腦：** 鑰匙只在發布的那台電腦，別台電腦要發同一份連結得按「重新產生連結」（舊的連結會失效）。
